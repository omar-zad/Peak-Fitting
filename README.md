# Constrained GIWAXS peak fitting

This repository contains the one-dimensional GIWAXS line-profile fitting
workflow used for a dissertation project. It fits FR, IP and OOP line cuts
with constrained Gaussian, Lorentzian and pseudo-Voigt components, compares
those line shapes by BIC, tests every component, and separates the numbers
that pass explicit reporting gates from the internal fit values that do not.

It contains small processed example line cuts, but no raw detector images,
NeXus/HDF5 files or unrestricted source data. The software and the example
data are licensed separately: see [LICENSE](LICENSE) and
[LICENSE-DATA.md](LICENSE-DATA.md).

## What the workflow does

For each configured q-window, the fitter:

1. fits all configured peak components plus a local polynomial background;
2. compares Gaussian, Lorentzian and pseudo-Voigt families using BIC across
   the active frames in that window;
3. favours a simpler profile when pseudo-Voigt improves BIC by less than 2;
4. tests each component by comparing the full model with a reduced model;
5. reports peak position, d-spacing, integrated area and apparent FWHM when
   the corresponding numerical and resolution checks pass;
6. saves overlays, individual components, residuals and an auditable table of
   all accepted, tentative and rejected fits.

No smoothing, vertical intensity offsets, MCMC or unconstrained exhaustive
search is used. The fit is a bounded nonlinear least-squares fit with a small
number of deterministic multistarts.

Profile selection is made per fitting window using all active frames. It is
not a majority vote over independently selected profiles for each peak.

## Scope: what generalises and what does not

**The fitter generalises.** `scripts/fitting/fit_giwaxs_series.py` operates on
any delimited table with q in the first column and one intensity column per
frame, described by a JSON configuration. Nothing in it is specific to this
sample, this beamline, or even to GIWAXS: any one-dimensional scattering or
diffraction profile with locally separable peaks can be fitted. To use it on
your own measurements you need only your profiles in that layout and a
configuration written from
[docs/CONFIGURATION_REFERENCE.md](docs/CONFIGURATION_REFERENCE.md).

**The preparation layer does not generalise.**
`scripts/preparation/prepare_secondary_scan.py` reads one specific acquisition
format: an SRS `.dat` header carrying `frameNo` and a `d5i` monitor, a
temperature table with `frame`, `time_s` and `temp3_C` columns, and per-sector
`1Dintegrations` CSV exports. It is published so that the provenance of the
committed inputs is auditable, not as a general-purpose importer. If you are not
working with that acquisition setup, skip it and hand your own q-plus-frames
table straight to the fitter.

## Repository layout

| Folder | Contents |
|---|---|
| `scripts/fitting/` | the fitter and one Drop40 sensitivity audit that drives it |
| `scripts/preparation/` | tools that build fitting inputs and JSON configurations |
| `scripts/diagnostics/` | unsmoothed key-frame plots used before fitting |
| `scripts/reporting/` | tools that combine fit outputs, apply gates and build reports |
| `scripts/calibration/` | optional instrumental-width diagnostic (needs pyFAI) |
| `scripts/provenance/` | one-off scripts that record how committed configurations were derived; kept as an audit trail, not runnable from a clone (see its README) |
| `configs/drop40/` | Drop40 base, retained and sensitivity configurations, all regenerated by `build_peakfit_cut_configs.py` |
| `configs/secondary_samples/` | the reviewed configuration for each secondary scan |
| `example_data/` | the Drop40 nine-frame line cuts and a secondary-scan frame manifest |
| `example_results/` | a verified first-frame reference run and the IP component-count comparison |
| `tests/` | regression and smoke tests (see Tests below) |
| `local_results/` | Git-ignored destination for everything you run |

Every documented command writes under `local_results/`, so a fresh clone stays
clean no matter what you run.

## Installation

Python 3.10 or later is required. Python 3.11 to 3.13 are tested.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

The calibrant-resolution script has additional packages:

```bash
python -m pip install -r requirements-calibration.txt
```

Those optional packages are not required for ordinary fitting of prepared 1D
q-intensity profiles.

## Reproduce the included Drop40 checkpoint

Run the deliberately short first-frame checkpoint:

```bash
python scripts/fitting/fit_giwaxs_series.py \
  example_data/drop40/drop40_FR_9frames_norm.txt \
  --config configs/drop40/peakfit_config_FR_revised.json \
  --outdir local_results/drop40_FR_checkpoint \
  --stage first \
  --bootstrap 0
```

Review these files before continuing:

- `local_results/drop40_FR_checkpoint/figures/first_frame_diagnostic.png`
- `local_results/drop40_FR_checkpoint/FIRST_FRAME_REVIEW.txt`
- `local_results/drop40_FR_checkpoint/figures/fits_<window>.png`
- `local_results/drop40_FR_checkpoint/fit_quality.csv`

A verified reference run is committed under
`example_results/drop40_FR_checkpoint/` for comparison, and the test suite
asserts that a re-run still matches it.

## Run all nine Drop40 frames and build the QC package

Only after the diagnostic has been accepted, run all nine frames for each cut:

```bash
for cut in FR IP OOP; do
  python scripts/fitting/fit_giwaxs_series.py \
    example_data/drop40/drop40_${cut}_9frames_norm.txt \
    --config configs/drop40/peakfit_config_${cut}_revised.json \
    --outdir local_results/drop40_${cut}_all \
    --stage all --confirm-first-fit --bootstrap 0
done
```

Each cut takes about a minute. Profile selection now uses all nine frames, so
a window may settle on a different line shape from the single-frame
checkpoint; that is expected and is the reason the checkpoint exists.

Then combine the three runs, apply the reporting gates and write the QC
package to `local_results/drop40_qc_report/`:

```bash
python scripts/reporting/build_nine_frame_qc_report.py
```

## Reproduce the Drop40 IP component-count comparison

The retained IP low-q model contains two components. Its component count was
checked by fitting one-, two- and three-component alternatives to the same
`q = 0.22-0.44 A^-1` data points in all nine frames, with the same linear
background and Gaussian/Lorentzian/pseudo-Voigt profile comparison. Bootstrap
was disabled because this is a model-selection test. The two-component run is
the `drop40_IP_all` run from the previous section.

```bash
python scripts/fitting/fit_giwaxs_series.py \
  example_data/drop40/drop40_IP_9frames_norm.txt \
  --config configs/drop40/sensitivity/peakfit_config_IP_1component.json \
  --outdir local_results/IP_1component \
  --stage all --confirm-first-fit --bootstrap 0

python scripts/fitting/fit_giwaxs_series.py \
  example_data/drop40/drop40_IP_9frames_norm.txt \
  --config configs/drop40/sensitivity/peakfit_config_IP_3component.json \
  --outdir local_results/IP_3component \
  --stage all --confirm-first-fit --bootstrap 0

python scripts/reporting/compare_component_models.py \
  --run one=local_results/IP_1component \
  --run two=local_results/drop40_IP_all \
  --run three=local_results/IP_3component \
  --outdir local_results/IP_component_count_comparison \
  --title "Drop40 IP low-q component-count decision"
```

The recorded BIC values were 905.2, 474.8 and 503.2 for one, two and three
components, respectively. The two-component model was therefore preferred by
Delta BIC 430.4 over one component and 28.5 over three components. Candidate
profile families were re-evaluated within each component-count model. The
verified comparison table and figure are committed under
`example_results/drop40_IP_component_count/`, and the slow test re-derives
these three numbers.

## Drop40 sensitivity checks

Two further checks quoted in the methods are reproducible from the committed
configurations. The reciprocal cross-sector test asks whether the q ≈ 0.459
Å⁻¹ IP feature has a counterpart in OOP and vice versa, on the four frames
between 65 and 80 °C:

```bash
python scripts/fitting/fit_giwaxs_series.py \
  example_data/drop40/drop40_IP_9frames_norm.txt \
  --config configs/drop40/sensitivity/peakfit_config_IP_q0480_cross_sector.json \
  --outdir local_results/cross_sector_0459_0480_sensitivity/IP \
  --stage selected --frames 197,198,199,200 --bootstrap 0

python scripts/fitting/fit_giwaxs_series.py \
  example_data/drop40/drop40_OOP_9frames_norm.txt \
  --config configs/drop40/sensitivity/peakfit_config_OOP_q0459_cross_sector.json \
  --outdir local_results/cross_sector_0459_0480_sensitivity/OOP \
  --stage selected --frames 197,198,199,200 --bootstrap 0

python scripts/reporting/summarize_drop40_cross_sector_sensitivity.py
```

The IP q ≈ 0.306 Å⁻¹ background-and-window sensitivity audit runs six fitter
variants and writes its own README to `local_results/IP_CCL_sensitivity/`:

```bash
python scripts/fitting/run_ip_ccl_sensitivity.py
```

## Fit a secondary scan

The full procedure, with the acceptance criteria for each stage, is in
[docs/SECONDARY_SAMPLE_PEAK_FITTING_WORKFLOW.md](docs/SECONDARY_SAMPLE_PEAK_FITTING_WORKFLOW.md).
In outline:

1. **Prepare the scan** (acquisition-format specific, see Scope). Copy
   `configs/secondary_samples/scan_registry.example.json` to
   `scan_registry.json`, fill in the local source paths, then run
   `python scripts/preparation/prepare_secondary_scan.py --scan <id>`. It
   validates frame, temperature and monitor alignment and writes the fitting
   tables, a frame manifest and a provenance file to
   `local_results/prepared/<sample>/scan_<id>/`.
2. **Look before fitting.** `scripts/diagnostics/plot_key_frames.py` plots the
   unsmoothed selected frames so that windows and component counts are chosen
   from the data.
3. **Build candidate configurations** with
   `scripts/preparation/build_secondary_sample_configs.py`. They start from the
   scan 587214 window library and are marked as requiring visual review; the
   committed configurations under `configs/secondary_samples/` are the reviewed
   and revised versions actually used.
4. **Fit the confirmed key frames** one cut at a time with
   `--stage selected --frames ... --bootstrap 0`, and inspect every
   `figures/fits_<window>.png`.
5. **Build the conservative tables** with
   `scripts/reporting/build_secondary_sample_report.py` and, where a numerically
   accepted position is visibly unreliable, record it in an exclusion CSV and
   apply `scripts/reporting/apply_manual_visual_qc.py`.

To re-run the committed configuration for a scan on its prepared table, for
example scan 587225:

```bash
python scripts/fitting/fit_giwaxs_series.py \
  local_results/prepared/<sample>/scan_587225/scan587225_FR_135frames_norm.txt \
  --config configs/secondary_samples/scan_587225/scan587225_FR_candidate_keyframes.json \
  --outdir local_results/scan_587225/FR \
  --stage selected \
  --frames 0,10,19,21,24,27,30,40,70,134 \
  --bootstrap 0
```

Do not assume a configuration from one sample is automatically valid for a
different sample.

## Important outputs

| Output | Meaning |
|---|---|
| `peak_parameters.csv` | Complete component table, including fitted and reportable values |
| `fit_quality.csv` | Optimiser, residual, BIC and bound diagnostics |
| `model_selection.csv` | Gaussian/Lorentzian/pseudo-Voigt comparison by window |
| `fitted_curves.csv` | Numerical data, total fit, background and components |
| `figures/fits_<window>.png` | Raw data, total fit, components and residuals |
| `figures/*_vs_temperature.png`, `figures/*_vs_frame.png` | Reportable position, area and FWHM per peak |
| `config_used.json` | Exact configuration snapshot used by the run |
| `run_metadata.json` | Input, frames, seed and software versions |
| `run_summary.txt` | Concise profile-selection and quality summary |

For series longer than about sixteen frames the diagnostic figures show a
representative subset and write every frame to a `<figure>_pages/` folder.

For secondary-sample reports, use `accepted_peak_positions_after_visual_qc.csv`
when present. A nonblank internal `q0_fit_Ainv` is not automatically an
accepted scientific result; the conservative gate uses `q0_reported_Ainv`.

## Tests

```bash
python -m pip install -r requirements-dev.txt
pytest -m "not slow"   # about 20 seconds
pytest                 # about five minutes
```

The quick set re-runs the committed Drop40 FR checkpoint and asserts that the
line-shape selection, fitted centres, widths, areas, BIC values, detection
status and reporting-gate outcome still match
`example_results/drop40_FR_checkpoint/`; checks that
`build_peakfit_cut_configs.py` regenerates every file under `configs/drop40/`
exactly; exercises the two other configuration builders on the example
manifest; and runs the component comparison on first-frame fits.

The slow test runs the whole Drop40 chain above (nine-frame FR, IP and OOP
fits, the component-count alternatives, the cross-sector fits, the QC package
and both summaries) and asserts the three BIC values quoted in this README.

Continuous integration runs the full suite on Python 3.10, 3.12 and 3.13.

## Scientific limits

- Confidence intervals are conditional on the selected peak/background model.
- The current profiles do not contain propagated pointwise measurement errors;
  empirical local noise is used for comparison and diagnostics.
- Apparent FWHM is not instrument-deconvolved.
- Do not convert secondary-sample FWHM values to CCL, crystallite size or
  strain without an appropriate instrumental-resolution treatment.
- A radial 1D profile alone cannot establish face-on/edge-on orientation or
  mosaicity; retain the corresponding 2D/azimuthal evidence.
